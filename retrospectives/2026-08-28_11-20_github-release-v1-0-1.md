# Ретроспектива: GitHub release v1.0.0 и corrective v1.0.1

## Задача и связи

Выпуск выполнен по [Plan v2 GitHub release](../plans/2026-08-23-github-release-v1-0-0.md) и source/consumer контракту из [`TEMPLATE.md`](../TEMPLATE.md). Публичный результат находится в [Codex Analyst Template](https://github.com/TomashPetersen/codex-analyst-template), а финальная hosted matrix зафиксирована в [GitHub Actions run 33104745676](https://github.com/TomashPetersen/codex-analyst-template/actions/runs/33104745676).

## Что сделано

- Создана публичная release-модель с tracked веткой `source`, производной consumer веткой `main` и annotated tags `v1.0.0` и `v1.0.1`.
- Исходный `v1.0.0` сохранен неизменным. Корректирующий `v1.0.1` закрепил кроссплатформенные temp и reparse fixtures после hosted проверки.
- Consumer `main` пересобран только из exact tag `v1.0.1` и содержит 185 переносимых файлов без source-only истории.
- Default branch установлена в `main`, включен GitHub Template mode, а About содержит короткую URL-first инструкцию для Codex.
- Реальный публичный clone и URL-first bootstrap создали независимый `generated-project + initialized + report-only` с Git `main` без remote.

## Что проверено и какими командами

- Полный локальный pre-tag профиль: TemplateSource structure, analysis self-test 86, Codex agents self-test 5, Plan lifecycle, canon/graph, Mastery, consumer boundary, bootstrap, distribution, knowledge, privacy и sanitizer - PASS.
- GitHub Actions run `33096366313` для corrective source commit - Windows и macOS PASS.
- GitHub Actions run `33104745676` для release source commit `52c736e` - Windows и macOS PASS.
- Remote refs и settings проверены независимо: `source`, `main`, оба annotated tags, default `main`, template flag и About соответствуют release contract.
- Fresh public `main`: DistributionTemplate gate, sanitizer 185, URL-first generated-project gate, branch `main` и отсутствие remotes - PASS.

## Что не получилось или осталось

- Исходный tag `v1.0.0` не изменялся после обнаружения кроссплатформенной несовместимости fixtures. Исправление выпущено отдельным immutable tag `v1.0.1`.
- GitHub Release binaries и package registry не создавались, так как они не входят в контракт шаблона.
- После terminal closeout остается только обычное сопровождение через новые Plan v2, без скрытых release-действий.

## Как было и как стало

До выпуска существовал проверенный локальный source без публичного подтвержденного install URL. После выпуска пользователь может передать Codex публичный URL и короткую команду: агент читает README и локальные инструкции, проверяет скачанный consumer, создает отдельный обезличенный проект и подтверждает его gates. Source history и maintenance fixtures остаются отделены от consumer `main`.

## Что выучено

- Immutable release tag безопаснее сохранять как исторический факт, а платформенное исправление публиковать отдельной версией.
- Hosted Windows/macOS matrix должна предшествовать формированию canonical consumer tag, если fixtures зависят от различий файловых систем.
- Public smoke обязан проверять не только clone, но и конечное состояние generated repository: режим, ветку, отсутствие remote и source-only leakage.
- Нового knowledge candidate не требуется: устойчивые выводы уже закреплены release-контрактом, changelog, проверками и этой историей выпуска.

## Security review

- Персональные данные: в consumer и source release не добавлялись; финальные privacy и sanitizer gates зеленые.
- Контент третьих лиц: новых заимствованных материалов не добавлено; лицензии и notices сохранены по manifest.
- Внешние отправки: ограничены явно разрешенным repository, ветками, tags и settings; force push и переписывание истории не применялись.
- Секреты: значения credentials не читались и не записывались; аутентификация выполнялась штатным credential flow.
