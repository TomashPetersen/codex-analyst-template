# Готовые запросы для работы с шаблоном

Открой установленную папку проекта в Codex и отправь один из запросов ниже. Замени значения в `<УГЛОВЫХ_СКОБКАХ>` своими данными. Если шаблон еще не установлен, начни с [запроса для установки](../CODEX-INSTALL-PROMPT.md). Порядок настройки после установки описан в [первом рабочем цикле](../README.md#первый-рабочий-цикл).

## 1. Заполнить паспорт проекта

Паспорт объясняет, для кого создается проект, какую проблему он решает и как проверить результат.

```text
Прочитай prompts/project-passport.md и выполни запрос из него.
Мой проект: <КРАТКОЕ ОПИСАНИЕ ИДЕИ ИЛИ ЗАДАЧИ>.
Задавай по 3-5 вопросов. Если я чего-то пока не знаю, отметь это
и помоги сформулировать следующий вопрос. Покажи заполненный PROJECT.md
и дождись моего подтверждения перед записью.
```

## 2. Настроить совместную работу

Профиль сохраняет предпочтения по общению и работе: как задавать вопросы, объяснять решения и показывать результат.

```text
Прочитай prompts/ai-clone-interview.md и выполни запрос из него.
Помоги настроить ai-clone/CORE.md для работы со мной.
Начни с формата общения, моих целей и требований к результату.
Задавай по 3-5 вопросов и покажи текст перед сохранением.
```

## 3. Выполнить первый анализ

Выбери один вопрос. Например: какие требования нужны для создания заявки или какие шаги текущего процесса требуют уточнения.

```text
Прочитай prompts/analysis-run.md и выполни запрос из него.
Задача: <ОДИН ВОПРОС ДЛЯ АНАЛИЗА>.
Исходные материалы: <ОПИСАНИЕ ИЛИ ПУТИ К ФАЙЛАМ>.
Выбери подходящий intent из mastery/INTENTS.json и задай task_ref
для этой задачи. Если материалов недостаточно, сначала уточни пробелы.
Создай один рабочий набор материалов анализа. Покажи выводы,
подтверждения, неизвестное и следующий шаг.
Основные документы проекта без отдельного разрешения не меняй.
```

## 4. Продолжить работу после перерыва

Этот запрос подходит, если работа уже ведется по сохраненному плану. Путь к нему есть в `plans/INDEX.md` и в ответе Codex при создании плана.

```text
Прочитай prompts/continue-plan.md и продолжи работу по плану
<ПУТЬ_К_ПЛАНУ_В_PLANS>.
Сначала сверь сохраненное состояние с файлами проекта.
Затем выполни следующий шаг текущей фазы и обнови план.
```

## Остальные задачи

Открой нужный файл, скопируй запрос и заполни пропуски. В столбце «План» указано, требуется ли сохраняемый план работы: `none` - не требуется; `required` - создать или найти один план; `existing` - продолжить указанный план.

## Правила для всех запросов

- Сначала прочитать `AGENTS.md`, `PROJECT.md` и указатель нужного раздела.
- Перед записью проверить, какие действия разрешены в текущем режиме репозитория.
- Не придумывать факты, подтверждения, согласие пользователя, цены, метрики или решения владельца.
- Разделять факт (`FACT`), наблюдение (`OBSERVATION`), гипотезу (`HYPOTHESIS`), мнение (`OPINION`) и цитату (`QUOTE`).
- Перед записью назвать точные пути; после записи показать изменения и результаты проверок.
- При `plan_policy: required` создать или найти ровно один план формата `Plan v2`; при `existing` полностью прочитать переданный `<PLAN_REF>`.
- Эти запросы сами по себе не разрешают выполнять `commit` или `push`, менять внешние системы, применять предложения для базы знаний или переносить аналитические выводы в основные документы. Для таких действий нужно отдельное прямое разрешение.
